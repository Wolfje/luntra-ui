# Button accessibility

What this component guarantees, why, and what it still needs from you.

## Guarantees

### It stays reachable while disabled

`disabled` renders as `aria-disabled`, never the native `disabled` attribute.

A natively disabled button is removed from the tab order. A screen-reader user
navigating by <kbd>Tab</kbd> never encounters it, so the action they came for
has not been _disabled_ from their point of view — it has silently ceased to
exist, with no explanation and nothing to ask about.

`aria-disabled` keeps the button focusable and announced ("Save, dimmed") while
the component blocks every route to activation: click, <kbd>Enter</kbd>,
<kbd>Space</kbd>, and implicit form submission. Those have to be blocked by hand,
because as far as the browser is concerned the element is still live.

The consumer's handler is not called at all while the button is inactive. That
is the one place in the library where the consumer's handler does not run first:
`disabled` is a guarantee, not a default.

**What you still owe the user:** say _why_. Pair the button with
`aria-describedby` pointing at an explanation.

```tsx
<Button disabled aria-describedby="save-hint">Save</Button>
<p id="save-hint">Add a title before saving.</p>
```

### The accessible name never changes while loading

`loading` sets `aria-busy` and keeps the children in the DOM. The spinner is a
CSS pseudo-element, so it is invisible to assistive technology.

Replacing the label with a spinner — or appending "Loading…" to it — changes the
accessible name mid-action. A screen reader announces that as a _different_
button, then announces it again when the action finishes. The user hears churn
and learns nothing.

**What you still owe the user:** announce the _outcome_. `aria-busy` says work is
happening; it does not say what happened. Put the result in a live region.

### Focus is always visible

`:focus-visible` draws a 2px outline with a 2px offset in `--luntra-color-focus-ring`,
which the token contrast tests hold to 3:1 against every surface it can appear
on, in every brand and both themes — WCAG 2.2 SC 2.4.13 (Focus Appearance).

`:focus-visible` rather than `:focus`, so a mouse click does not leave a ring
behind. The heuristic browsers already ship is better than anything reimplemented
on top of it.

### Targets are large enough

Every size clears the 24x24 CSS pixel minimum of SC 2.5.8, enforced with
`min-height` so that a one-character label cannot shrink it below the floor.
`size="lg"` reaches 44px, the AAA figure from SC 2.5.5.

### Motion respects the user's preference

Under `prefers-reduced-motion: reduce`, colour transitions drop to zero and the
spinner switches to an eight-step 1.5s rotation.

It steps rather than stopping. SC 2.3.3 asks for motion to be removable, but a
frozen spinner reads as a hung interface — the user needs to know the work is
still running.

### It survives Windows High Contrast Mode

Forced-colors mode replaces every author colour, collapsing the variants into
each other and potentially erasing the focus ring. The component restores a
`ButtonText` border, forces the focus outline to `Highlight`, and marks the
disabled state with `GrayText`.

### It renders correctly before hydration

Every attribute above is in the server HTML. A button that is briefly live, or
briefly unstyled, during the first few hundred milliseconds of a page's life is a
real defect on a slow connection — and one that never shows up in local testing.

## Choosing the right element

Use `render` when the control navigates:

```tsx
<Button render={<a href="/pricing" />}>Pricing</Button>
```

The component recognises three cases and adapts:

| `render`               | Role     | Keyboard                                    | Notes                                                 |
| ---------------------- | -------- | ------------------------------------------- | ----------------------------------------------------- |
| omitted, or `<button>` | `button` | <kbd>Enter</kbd> + <kbd>Space</kbd>, native | `type="button"` by default                            |
| `<a href="…">`         | `link`   | <kbd>Enter</kbd>, native                    | Keeps the link role, context menu and open-in-new-tab |
| anything else          | `button` | <kbd>Space</kbd> synthesised                | `role` and `tabIndex` added                           |

An `<a>` is deliberately **not** given `role="button"`. Announcing it as a button
while it still navigates takes away the context menu, open-in-new-tab, and the
user's correct expectation of what pressing it does.

An `<a>` _without_ an `href` is treated as a custom element, because it is
neither focusable nor a link.

## What the component cannot do for you

- **Give it a name.** An icon-only button needs `aria-label`. SC 4.1.2.
- **Make the label meaningful.** "Click here" passes every automated check and
  fails every user. SC 2.4.6.
- **Warn anybody.** `variant="destructive"` styles a button red. It does not warn
  anyone, and it is invisible to a screen reader. If an action is irreversible,
  say so in the label or confirm it. SC 1.4.1 — colour is never the only signal.
- **Manage focus after the action.** If pressing the button removes it from the
  page or opens a dialog, move focus deliberately. SC 2.4.3.
- **Announce results.** Use a live region.

## How this is verified

| Where                     | What it proves                                                                                                                          |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `tokens.contrast.test.ts` | Every colour pair meets its ratio, in every brand, both themes, across resting/hover/active                                             |
| `button.test.tsx`         | Behaviour: focusable while disabled, activation blocked on every route, stable accessible name, keyboard operation of each element kind |
| `button.a11y.test.tsx`    | axe finds no violations across every variant, size and state                                                                            |
| `button.ssr.test.tsx`     | The server HTML already carries the correct semantics                                                                                   |

axe catches roughly a third of real accessibility problems, so it is a
regression net rather than a certificate. The guarantees above are asserted
behaviourally, and the contrast ratios are proved against the tokens rather than
sampled from a screenshot.
